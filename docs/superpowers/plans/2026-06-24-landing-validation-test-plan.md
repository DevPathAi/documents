# Test Plan: DevPath AI landing validation smoke test

Generated by /plan-eng-review on 2026-06-24
Repo: dev-path-ai

## Affected Pages/Routes

- One-screen smoke-test landing page — validate Korean CTA, consent, Step 1 registration, Step 2 inline profiling, success/error states.
- Apps Script Web App endpoint — validate JSON `doPost(e)` handling, Google Sheets upsert, idempotent updates, and sensitive-input rejection.
- Google Sheets validation workbook — validate tabs and computed/manual fields for lead scoring, interview pipeline, and Round 2 report inputs.

## Key Interactions to Verify

- User submits Step 1 with email, current stage, required consent, and UTM/referrer data.
- User sees Step 2 inline after confirmed Step 1 save.
- User submits Step 2 with stack, recent stuck moment, optional WTP, and interview opt-in.
- User retries after a failed Apps Script response without losing short in-progress form values.
- User double-clicks submit and only one row is created or updated.

## Edge Cases

- Missing consent is rejected.
- Invalid email is rejected.
- Duplicate email normalizes to the same lead row.
- Existing `lead_id` updates the same row.
- Empty Step 2 fields do not erase prior non-empty values.
- UTM/referrer/landing variant are preserved from Step 1.
- `consent_version` and consent timestamp are stored.
- Sensitive patterns are warned or blocked: GitHub URLs, `http`, `password=`, `token`, `BEGIN PRIVATE KEY`, `.env`, JDBC URLs, and long stack-trace-like multiline input.
- Normal Korean 1 to 2 sentence pain descriptions pass.

## Critical Paths

- Step 1 insert -> confirmed save -> Step 2 inline expansion.
- Step 2 update -> same row updated -> completion copy shown.
- Apps Script failure -> retryable error -> local draft preserved -> retry succeeds -> local draft cleared.
- Sensitive input -> blocked/warned -> edited safe input -> successful submission.
